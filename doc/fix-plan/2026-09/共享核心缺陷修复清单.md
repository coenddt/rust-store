## 修复项（按优先级）

### 红线 · 权限与危险操作（P0）
- **R1** `core/command/query.rs` `merge_owner_condition`：schema read 含 `creator` 时注入 `createdBy=ctx.userId` 到 read/count/aggregate。验收：E-07/08/09/12/15 只回本主行。
- **R2** `core/command/write.rs`：`write:[]` 一律拒绝（403 `ERR_PERMISSION`）。验收：B-16 insert AuditLog 抛错。

- **R4** 写规划：空条件拒绝 `update_many/remove`（不落全表）。验收：B-10。
- **S1** `dialect_translate`：数组/对象字段不可翻译条件 → 显式 Err 或告警，禁止静默返回全表。验收：G-01/02/03/04/06/07/10，A-03/06/13/14。

### 数据正确性（P1）
- **R5** `plan_query_with_count`：`page/pageSize(或 skip/limit)` 落库 LIMIT/OFFSET。验收：A-18 前 3 行。**连带**：收敛 py/node 宿主 hasMore 塑形（见两端文档）。
- **R6** `core/command/write.rs`：对象字段 `$set` 整体替换，不作深合并。验收：B-05 仅 `{cover:"x"}`。
- **R8** 计算列 lookup 求值：`lessonCount` 物化出值。验收：D-03 c1=2/c7=0。
- **R9** `query.rs` `has_pipeline → projection`：决策是否对用户 `$pipeline` 施加外层投影（当前显式跳过）。验收：D-08 仅 `{_id,title}`。
- **R10** `dialect_translate`：数组子字段 `depends`（`lessons{duration}`）→ 显式 Err 或告警，禁用非法列 `t.lessons{duration}`。验收：原 D-07 SQL 侧不再生成非法 SQL。

### 可移植一致（P2）

- **S4** 关系读裁剪：关系目标 read 在投影/还原时裁剪。验收：E-05/11。

## 修复进度（2026-09-13 增量）
### R2 · 写权限空名单拒写（B-16）—— **已修复**
- 根因：`permission.rs can_write_schema` 把 `write=[]`（显式空白名单）与 `write=None`
  （无配置）混同为「无角色白名单 → 走默认放行」，导致 `write=[]` 的只读 schema 仍可被
  普通角色写入。
- 修复（`core/src/permission.rs can_write_schema`）：`write` 显式为空数组时拒绝一切写，
  仅 super_admin/admin 保留编辑权，internal 放行。
- 影响：js/node 同源继承，无需改绑定。

### R4 · 空条件批量写一票否决（B-10/**B-12**）—— **已修复**
- 根因：`plan_update_many` 只过 `validate_condition`，无条件（空 `{}`/空逻辑组）时仍
  生成无 WHERE 的 UPDATE/DELETE，存在落全表风险（历史 B-10/B-12）。
- 修复（`core/src/command/mutate/many.rs` + `single.rs` + `mod.rs`）：新增共享
  `is_blank_condition`（`{}`/`null`/空数组/全空逻辑组判定），`plan_update_many` 与
  `plan_remove` **双双**命中即 `Err(ERR_NO_BATCH_WRITE)`。B-12（`remove({})` 落全表致
  count 7→0）此前漏网，本轮一并封堵。
- 影响：js/node 同源继承。

### R3 · 危险阶段拦截（G-05/G-08/G-09）—— **已修复**
- 根因：聚合 pipeline 无阶段级拒绝名单，`$out`/`$merge` 写副作用可透传；用户 `$pipeline`
  分支未过名单（G-08）；`$expr` 可引用 schema 外字段（G-09）。
- 修复（`core/src/types.rs`）：新增 `validate_pipeline_stages`（拒 `$out`/`$merge` 写
  副作用阶段、递归拒危险算子、校验 `$expr` 字段引用）+ `EXPR_OPS` 运算符表。
- 接线：`command/write.rs plan_aggregate` 与 `command/query.rs` 的 `$pipeline` 分支均调用。
- 影响：js/node 同源继承。

### R1 · owner(creator) 读权注入 —— **已完整修复（query/count/aggregate/关系全路径）**
- 根因（E-07/E-15）：`command/query.rs plan_query_ast_mut` 的 owner 注入被

- 修复（`core/src/command/query.rs`）：解开门控，无 `$condition` 时注入合成条件
  `@__core_owner__`（`{"createdBy": ctx.userId}`）为基准 `$match`。
- 修复（`core/src/command/write.rs`）：`plan_count` 增加 `ctx` 参数并
  `merge_owner_condition`；`plan_aggregate` 增加 `ctx` 参数并把 owner 条件注入

- 修复（`core/src/pipeline/lookup.rs` + `build.rs`）：`build_lookup` 对关系目标

  参数并透传；`py-store` 宿主 `crud/write.py count`、`crud/mutation.py aggregate`
  调用补传 `_ctx()`。**nodejs 同源继承该修复，node 绑定已同步改签名。**
- 结果：

  - sqlite：38→42/88，E-07/E-08/E-15 通过（owner 注入跨 SQL 方言生效）。

### S1 · 不可翻译 filter / 聚合阶段显式报错（G-01/G-02/G-10）—— **已修复**
- 根因：`dialect/filter/mod.rs field_clauses` 对 object/array 复杂 JSON 字段（`tags`、
  `coupon.code`、`meta.seo.title`）或未声明字段的过滤条件，`scalar_column` 返回 `None`
  后 `continue` 静默丢弃 → 生成缺该条件的 WHERE → 返回全表；`aggregate.rs` 对 `$group`
  等未实现阶段同样静默忽略 → 返回未聚合的原始行。
- 修复（`core/src/dialect/filter/mod.rs`）：`column(field)=None` 时不再 `continue`，
  改为显式 `Err`（S1/D-02 契约：不可翻译即报错，绝不静默丢弃；读路径 + 写路径 `WHERE`
  同受保护）。
- 修复（`core/src/dialect/select/aggregate.rs`）：阶段分发补充兜底 `else`，未实现阶段
  （`$group`/`$unwind`/`$addFields`/`$count`/`$facet`）显式 `Err`。
- 影响：js/node 同源继承（方言层无绑定差异）。

### R5 · 分页落库 LIMIT/OFFSET（A-18）—— **已修复**
- 根因：`plan_query_with_count` 已从 params 解析出 `page/pageSize`，但仅当 GQL
  AST 显式引用 `$skip/$limit` 时才写回 params；A-18 的 GQL `Course($sort:@s0){_id}`
  未引用两者 → `build_pipeline` 不产生 `$skip/$limit` 阶段 → 返回全表，`items` 超分页。
- 修复（`core/src/command/count.rs plan_query_with_count`）：当 params 含
  `page|pageSize` 且 GQL 未引用 `$skip/$limit` 时，注入合成引用
  `@__core_page_skip__/@__core_page_limit__` 并写入 params；随后改用
  `plan_query_ast_mut` 走同一条 AST 规划路径（不再用原 gql 二次 parse）。
- 影响：js/node 同源继承（count.rs 为核心逻辑，无绑定差异）。
- 结果：mongodb 67→68、sqlite 49→50；A-18 双端 pass，无回归。

### R6 · 对象字段 `$set` 整体替换（B-05）—— **核心读语义已修（oracle 侧）**
- 根因：写侧实际已是「整体替换」（Mongo `$set:{meta:{cover:"x"}}` 原生落盘
  `{cover:"x"}`）；失真发生在**读后处理** `fill_nested_objects` —— 请求整个
  object 字段时同步补回所有缺失子字段默认值（`level`/`seo`），使返回形状既非
  存储值、又伪装成深合并。
- 修复（`core/src/computes/run/sync.rs fill_nested_objects`）：仅当 GQL 以点号
  精确引用子字段（`meta.seo.title`）才补缺失子字段默认值；请求整个 object 字段
  （`meta`）时**原样返回存储值**，不做嵌套默认值回填。
- 影响：js/node 同源继承。
- 结果：mongodb oracle **68→70**（B-05、H-10 双过），无回归；sqlite 无回归
  （B-05 仍受 SQL 严格关系范式限制 —— object 字段不落列、无法持久化，属独立
  架构局限，非本项读语义范围）。

### R8 · lookup 计算列物化（D-03）—— **已修复**

- 修复（`core/src/schema/registry.rs`）：`parse_computes` 新增 `merge_lookup_add_fields`，

- 修复（`core/src/pipeline/projection.rs`）：`build_projection` 对数据库阶段已物化的
  lookup 计算列（`!has_fn && !has_async_fn && lookup.is_some`）在顶层 `$project` 保留。
- 修复（`core/src/pipeline/build.rs` + `lookup.rs`）：`build_compute_lookup_stages` /
  `build_add_fields` 增加 `requested` 过滤，**仅当计算列字段被 GQL 请求**才发射 `$lookup`/

- 影响：js/node 同源继承。

### R7 · asyncFn 普通字段依赖注入（D-02）—— **已修复**
- 根因：asyncFn 计算列（`User.displayName`、`depends=["name"]`）依赖的**普通根字段**

  - `merge_depends_into_ast` 之外，`plan_query_ast_mut` 对非 `$pipeline` 路径把

### S3 · 关系 one→对象 / many→数组 形状 + 嵌套关系解析 —— **已修复**
- 根因（C-01/03/05/07/08）：`sync.rs descend_relations` 对无匹配关系的处理缺形状契约——
  关系无匹配时直接跳过（缺键），不落 `one→null` / `many→[]`；且关系目标子文档「是否保留
  `_id`」未按 GQL 是否显式请求 `{_id}` 判定（C-09/C-10 读投影漏剪）。
- 修复（`core/src/computes/run/sync.rs descend_relations`）：
  - **形状契约**：one 关系无匹配 → 落 `null`，many 关系无匹配 → 落 `[]`，既不但边齐全、
    也不一边 `[]` 一边 `null`（对齐 C-01/C-07/C-08）。
  - **`_id` 读裁剪**：仅当 GQL 显式请求 `{_id}` 才保留关系子文档 `_id`，否则剥除
    （对齐 C-09/C-10，S4）。
- **嵌套关系解析**（C-05）：`pipeline/lookup.rs build_rel_projection` 只按 `rel_ast.fields`
  投影，**未保留嵌套关系名**，导致多对多父级（`lessons`）最终 `$project` 把子级已解析的
  嵌套 one 关系（`lessons.parent`）丢弃 → parent 恒 null。修复：投影补充
  `rel_ast.relations` 的关系名，保留嵌套 lookup+$unwind 已落位的对象/数组。
- 影响：js/node 同源继承。
- 结果：mongodb oracle **75 → 83/88**，C-01/03/05/07/08/09/10 全部通过；
  sql/mysql/postgres **53 → 54/88**（C 组 SQL 多为显式 `$unwind`/`childLimit` 不支持，
  符合「可译则 Err、绝不静默」契约，非缺陷）。

### S4 · 关系读裁剪 —— **随 S3 一并落地**
- `descend_relations` 的 `keep_id` 判定即 S4 的关系目标读裁剪：GQL 关系内未显式
  `{_id}` 时，关系子文档 `_id` 被剥除（C-09 category 只回 `{name}`、C-10 lessons 只回
  `{title}`）；同时外层 `process_node` 的权限/字段裁剪递归覆盖关系子文档。

### C-04 · 自关联 children 递归闭包 —— **测试预期与数据/关系定位不一致（登记，非核心缺陷）**
- 现象：所有后端一致返回**直接子**（`foreignField:parentId` 语义）：cat1.children=[cat2]、
  cat2.children=[cat3]、cat3.children=[]；但用例 `expect` 写 cat1.children=[cat2,cat3]
  （含孙级 cat3）。
- 依据：seed 为链式 `parentId`（cat3.parentId=cat2），`children` 关系定位为
  `localField:_id, foreignField:parentId` → 直接子本就是一层；任何后端（含 mongo oracle）
  都取直接子，四端一致。
- 结论：C-04 的 `expect` 与 seed 数据自相矛盾。若要满足「含孙级」，需在全部后端实现
  自关联**递归闭包（WITH RECURSIVE / Mongo 多层 lookup）**，这与关系定位语义冲突、且为
  大范围跨方言增强。**暂不强行实现**，登记测试素材修正建议，待场景作者确认子树语义。

### 写路径保留显式 null（H-01 读回 / F-07 落盘）—— **修复（`core/src/command/write.rs`）**
- 根因：`build_insert_doc` 把 `null` 一律当缺失剔除，导致「空串/NULL/缺失」三态

### Mongo 三态 filter 翻译（F-07）—— **宿主边界改写（`py-store/src/py_store/executors/mongo.py`）**
- 根因：Mongo 原生 `{f: null}` 同时命中「null」与「缺失」，与本 store 三态契约冲突
  （应 null 只命中显式 null、`$exists:false` 才命中缺失，对齐 SQL `col IS NULL`）。

  运算对象（`$ne:$exists:$gt`…）不改写。nodejs 宿主同步实现同源改写。

### SQL `$eq/$ne` null 译为 `IS NULL`/`IS NOT NULL`（H-06 等）—— **修复（`core/src/dialect/filter/op.rs`）**
- 根因：`$eq: null` 生成 `col = NULL`、`$ne: null` 生成 `col <> NULL` → SQL 三值逻辑下恒否，
  显式 null/非空行都读不到。
- 修复：新增 `null_eq_ne`，取值 null 时 `$eq`→`IS NULL`、`$ne`→`IS NOT NULL`（无参数）；
  对象算子（`$eq/$ne`）与直接值简写双路径生效。跨后端（sqlite/mysql/postgres）一致。

## 修复进度（2026-09-13 增量三）· 缺失 vs null 三态（present-key 哨兵）
目标项：F-07 / A-19 / H-01 / H-02 / H-09 —— SQL 侧「缺失 vs null」三态对齐 mongo oracle。
方案（core 全后端统一）：SQL 定宽列无法区分「缺失」与「null」⇒ 引入 **`__present` 哨兵列**
（每行存 `,field,` 令牌集合，标量显式存在即入列，含显式 null、剔除缺失）。

- **DDL（`py-store/example/course-platform/ddl/{sqlite,mysql,postgres}.sql`）**：各表补
  `__present TEXT`（mysql 为 `VARCHAR(255)`）。
- **写路径（`core/src/dialect/write/insert.rs`）**：`present_value` 落集 —— 根标量键
  （含 `_id`/注入时间戳）拼入 `__present`。
- **写维护（`core/src/dialect/write/update.rs`）**：`present_expr` 维护 SET 集 ——
  `$set/$inc` 追加令牌、`$unset` 用 `REPLACE(..., ',k,', ',')` 移除；一律裸列名
  （UPDATE SET 目标不带表别名，SQLite 才接受）。
- **读路径（`core/src/dialect/select/{find,aggregate}.rs`、`write/mod.rs#returning`）**：
  SELECT 追加 `t.__present AS __present`，并把 `present_alias` 注入 `RowShape`。
- **行还原（`core/src/dialect/row.rs`）**：`merge_path` 标量 null 时**仅当字段在 present 集**
  才产出 `key:null`，否则不产出键（缺失无键）⇔ Mongo「显式 null 有键、缺失无键」。
- **filter 翻译（`core/src/dialect/filter/op.rs`）**：
  - `$eq:null` → `col IS NULL AND COALESCE(alias.__present, ',') LIKE '%,field,%'`（只命中显式 null）；
  - `$ne:null` → `col IS NOT NULL`；`$exists` → `NOT LIKE` 判定存在性（含显式 null，别于缺失）。

### MySQL 宿主转义修复（增量三收尾）—— `py-store/src/py_store/executors/mysql.py`
- 根因：`_to_pyformat` 只把 `?`→`%s`，未转义字面 `%`；present_key 的 `LIKE '%,field,%'`
  在 asyncmy/PyMySQL 的 `execute(sql, args)`（内部 `sql % args`）下被误作格式说明符，
  报 **`not enough arguments for format string`**（A-19/H-09）—— sqlite/postgres 用
  `?`/`$N` paramstyle 不受影响，故仅 mysql fail。
- 修复：`_to_pyformat` 把引号内外的字面 `%` 一律转成 `%%`，`?` 仍仅在引号外转 `%s`。
