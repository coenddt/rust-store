## 关键推论
1. **13 项缺陷 11 项在共享 Rust 核心** → 修复优先级最高；建议全部落在 core 单点修复，py/node 仅做对拍验证 + 宿主去重。
2. **仅 R7、R5 涉及宿主**（R5 宿主塑形重复、R7 asyncFn 尾处理各端独立），其余 py/node 均「继承 core 修复」，无重复实现负担。
3. **nodejs 全面受同一批缺陷影响**（同一核心绑定），但 nodejs-store 目前无本场景回归套件 → 核心修复后需在 nodejs-store 补冒烟/对拍用例，避免「一处修、一端漏验证」。
4. **减少造轮子落地项**：R5 的 `queryWithCount` 结果塑形在 py `crud/query.py` 与 node `crud/query.js` 重复实现 → 建议随核心分页修复一起收敛（可保留薄宿主或统一由 core 返回包络）。

## 验收基准
- py：`python -m pytest py-store/tests/test_scenario_course_platform.py -q`，目标三 SQL 后端 ≥58/88（追平 mongodb）。
- node：补 `nodejs-store` 同语义词面冒烟，覆盖 R1/R3/R6/R8/R9 关键路径。
- 全核心修复后：三 SQL 后端与 mongodb 结果集逐行一致达 100% 已是诱因，缺键/形状待对齐项另归测试素材。
